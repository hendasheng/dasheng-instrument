# Loudroom 0.2

状态：本地开发草稿，未发布。GitHub Pages 继续使用已发布的 0.1；小工具保持 0.1，不同步。

## 首要问题：和弦按法与 CAGED 的关系不清楚

项目要帮助使用者把音、指板位置、声音和实际手部动作对应起来。当前页面虽然显示了正确的内容，却没有形成清楚的练习路径；不能把两个独立模块的并列展示当作 CAGED 教学已经完成。

当前实际行为：

- 和弦模块展示当前大调的七个调内和弦及独立 V7，每个和弦仅提供一种按法。
- Fretboard Map 的 CAGED 按钮按字母筛选音阶把位区域，没有画出对应的和弦形状；现有算法只是按调平移的固定四品窗口，不是完整、经过验证的 CAGED 指型模型。
- 两模块只共享当前调与绘图组件，交互独立。尚未表达“同一个和弦在不同把位的 C/A/G/E/D 形状”。
- CAGED 字母表示形状，不表示把和弦换成该字母的和弦；例如 C 和弦可以使用 C 形或 A 形，组成音仍为 C/E/G。

后续设计必须先解决：

1. 区分调内级数、和弦名称、具体按法、CAGED 形状和音阶把位，避免把不同概念作为同一级控制。
2. 决定清楚的练习路径，让用户知道当前看的是哪个和弦、哪种形状、哪些实际位置。
3. 验证 CAGED 数据与把位模型，再讨论两个模块如何协作；不要直接替换主指板标记而留下失效或矛盾的音阶控制。
4. 保留原有音阶播放、循环、标签与把位功能。未经明确设计，不再强行联动。

先整理概念与交互方案，再继续扩展功能。当前 0.2 不具备发布条件。

## 已有草稿实现

- 所有调内和弦同时展示，V7 单列；支持逐音试听、Play 图标试听及整体收起/展开。
- 音阶图与和弦按法图共用 apps/web/src/Fretboard.tsx；已移除 ChordKit 依赖。
- 和弦图使用竖向排列、音名、品位点、空弦/不弹标记与连续横按。按弦实心、空弦空心。
- 卡片仅保留一层轻边界；小图琴枕弱化。布局、横按位置及可读性仍需整体视觉验证，不能仅以构建通过作为验收。
